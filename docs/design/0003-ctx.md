# 0003: Request context (`ctx`)

Status: Approved
Packages: `ctx` (roadmap 0002, step 3). No file outside `ctx/` changes; `core` compiles unchanged.

## Goal
`ctx` is on every request: it creates the context, reads the request (query, body, form, files, params,
headers), binds it into structs and writes the response. After this change it survives hostile input
without a 500, costs a fraction of today's time and allocations, and offers handler injection a binding
plan that is built once per struct type instead of walked with reflection on every request.

WS context is out of scope; it changes only through the shared `contextID` (B24), the shared body
binder (`WSPayload.Bind` uses the same plan as `Body.Bind`) and the aggregation slot design 0005
asks for on both contexts (B36).

Measured on Go 1.27.4, darwin/amd64, i7-9750H. Go 1.27's `encoding/json` runs on the v2 engine; the
JSON numbers below depend on it.

## Public API

### Changed (breaking)
```go
func (c *HTTPContext) JSON(data any, args ...any)    // was JSON(data ...any)
func (c *HTTPContext) JSONP(data any, args ...any)   // was JSONP(data ...any)
```
Every call with at least one argument compiles unchanged. `c.JSON()` with no argument, which panics
today with an index error (B16), stops compiling.

Removed: `ctx.DataWriter`, `ctx.JSON`, `ctx.JSONP`, `ctx.Text` (the writer types of `ctx/writer.go`;
all their fields are unexported, so no caller can build one) and the file `ctx/writer.go`. Not
re-exported by `aliases.go`, not used outside `ctx`.

### Added
```go
type JSONAppender interface {
	AppendJSON(dst []byte) []byte
}

type Binder struct{ /* unexported */ }

var ErrBindTarget = errors.New("ctx: bind target must be a struct")

func BinderOf(t reflect.Type) (*Binder, error)

func (b *Binder) StrArr(d map[string][]string) (any, []FieldLevel)
func (b *Binder) Header(h Header) (any, []FieldLevel)
func (b *Binder) Struct(d map[string]any) (any, []FieldLevel)
func (b *Binder) File(f File) (map[string][]*DataFile, any)

func (c *HTTPContext) AddAggregation(a *aggregation.Aggregation)
func (c *HTTPContext) Aggregations() []*aggregation.Aggregation
func (c *WSContext) AddAggregation(a *aggregation.Aggregation)
func (c *WSContext) Aggregations() []*aggregation.Aggregation
```
The last four are the per-request slot design 0005 expects (it replaces `context.WithValue` in the
interceptor middleware). `ctx` imports `aggregation`, which imports nothing.

### Unchanged signatures, new implementation
`NewHTTPContext`, `Init`, `Reset`, `Status`, `Text`, `Redirect`, `SetID`, `GetID`, the six accessors
(`Body`, `Form`, `Query`, `Header`, `Param`, `File`), the `Get / Set / Add / Del / Has / Bind` methods
of each type, `BindStruct`, `BindStrArr`, `BindFile`, `GetTagParams`, `GetTagParamIndex`, `TagBind`,
`RequestID`, `FieldLevel` and its getters, `DataFile`, the fields `ParamKeys`, `ParamValues`, `Next`,
`Code`, `Timestamp`.

`X.Bind(s)`, `BindStruct`, `BindStrArr` and `BindFile` become thin wrappers over `BinderOf`.

### Binding API offered to handler injection (`core/fn.go`, design 0006)
- `BinderOf(reflect.Type)` builds the plan of a struct type once and caches it per type (a
  `sync.Map`, as `fieldBindTagCache` does today at `ctx/fn.go:59`). Injection calls it at `Create()`
  for every pipe argument type that is a struct: this warms the cache and reports `ErrBindTarget`
  early. It is best effort: a `Transform` may bind another type, which is then built on its first
  request.
- The per-request call stays in user code (`bound, _ := q.Bind(dto)` inside `Transform`). On a warm
  type it costs one cache load and no type walking, tag parsing or `fmt`.
- Injection may hold a `*Binder` and call `StrArr / Header / Struct / File` directly if it ever binds
  without a user `Transform`.
- The accessors return in O(1) after the first call in a request and never return `nil` for `Body`,
  `Form`, `Query`, `Header`, `Param` (B8, B12). `File()` has length 0 when the request has no files.

## Behavior

Unless a rule says otherwise, today's results are kept exactly: the bound value, and the
`[]FieldLevel` (one entry per tagged, exported field in declaration order, nested entries before
their parent, same `Tag / NestedTag / Namespace / Field / Index / Kind / Type / Value / IsValue`).
A value of the wrong JSON type for a scalar field leaves the field zero and adds no `FieldLevel`
(today's policy, called "mismatch" below).

### Bugs fixed: binding
Each one is reproduced by the input given; all of them are a client-triggered or always-on 500 today.

- **B1** `ctx/fn.go:88` (`reflect.Value.Set` with the unnamed value). Field of a named basic type:
  `type Page int; struct{ P Page `bind:"page"` }` with `Query{"page": {"2"}}` or `Body{"page": 2.0}`
  panics `reflect.Set: value of type int is not assignable to type Page`; `[]Page` panics the same
  way. Rule: named bool, integer, float, complex and string types, and slices of them, bind like
  their underlying type; the field holds `Page(2)` and `FieldLevel.Value()` is `Page(2)`.
- **B2** `ctx/binding.go:103-108`. Field `Meta any `bind:"meta"`` with body `{"meta": null}` panics
  (`Set on zero Value`). Rule: the field stays `nil`; one `FieldLevel` with `IsValue() == true` and
  `Value() == nil`. Same for `*any`: pointer to a nil interface.
- **B3** `ctx/binding.go:141-142`. Struct field `Addr Addr `bind:"addr"`` with `{"addr": "x"}`,
  `{"addr": 1}`, `{"addr": []}` or `{"addr": null}` panics on an unchecked type assertion. Rule:
  mismatch (field zero, no `FieldLevel`, no panic).
- **B4** `ctx/fn.go:463` → `ctx/binding.go:121`, `ctx/fn.go:940` → `ctx/binding.go:136`. Slice or map
  whose element kind is not supported (`[]*Addr`, `map[string]*Addr`, `[]chan int`) with a JSON array
  or object panics (`Set on zero Value`). Rule: the field stays zero, no `FieldLevel`, no panic.
- **B5** `ctx/fn.go:708-889` (every `objValue.(map[string]any)`). `map[string]map[string]int` with
  `{"m": {"a": 1}}` panics. Rule: an inner value that is not an object is skipped (the key is absent
  from the result); other keys bind.
- **B6** `ctx/fn.go:338` (`reflect.TypeOf(el).Kind()` on `nil`). `[][]int` with `{"g": [[1, null]]}`
  or `{"g": [null]}` panics with a nil dereference. Rule: `null` elements and `null` rows are skipped:
  the results are `[][]int{{1}}` and `[][]int{}`.
- **B7** `ctx/binding.go:87`, `ctx/fn.go:115-270`, `482-662`. A JSON number outside the field type's
  range is converted with a Go float-to-integer conversion, whose result is implementation-defined:
  `int8` ← `300` gives `44`, `int` ← `1e300` gives `math.MinInt64` on amd64. Rule: a number outside
  the range of the target integer or `float32` type is a mismatch for a scalar field or pointer; in a
  slice or map it is a wrong-type element (today's rule for those: the whole slice or map becomes
  empty; in nested slices the element is skipped). Fractions keep truncating toward zero (`1.9` →
  `1`); negative numbers are already refused for unsigned slices and maps and are now refused for
  unsigned scalars too (`uint8` ← `-1` is a mismatch, today `0`).
- **B14** `ctx/http_header.go:45-48`. `Header{"X-Token": {"t"}}.Bind` into a field tagged
  `bind:"x-token"` leaves it empty, while `Header.Get("x-token")` finds it. Rule: `Header.Bind` and
  `Binder.Header` look each tag up by its canonical MIME header form, computed once in the plan;
  `FieldLevel.Tag()` keeps the tag as written.
- **B23** `ctx/http_query.go:42` and siblings (`reflect.TypeOf(s).NumField()`). `q.Bind(&dto)`,
  `q.Bind(nil)` or `q.Bind(42)` panic with a reflect message or a nil dereference. Rule:
  `BinderOf(t)` returns `ErrBindTarget` when `t` is `nil` or not a struct type; `X.Bind`,
  `BindStruct`, `BindStrArr`, `BindFile` panic with an error for which
  `errors.Is(err, ErrBindTarget)` is true. `BindStruct` keeps accepting a `reflect.Type` as `s`.
- **B25** `BinderOf` on a self-referential type (`type Node struct { Children []Node `bind:"children"` }`)
  returns without recursing forever, and binds nested data to any depth the body holds.

### Bugs fixed: request reading
- **B8** `ctx/http_body.go:37`. Body `null` with `Content-Type: application/json` sets the cached map
  to `nil`; the first `Body()` returns `nil` (`Body().Set` panics), the second reads the drained body
  again and panics `unexpected end of JSON input`. A handler that injects `ctx.Body` twice (itself
  and a body pipe) hits it. Rule: `Body()` never returns `nil`; `null`, an empty body and a body of
  only JSON whitespace give an empty `Body`, read once and cached.
- **B9** `ctx/http_body.go:35-39`. Malformed JSON, or a top-level value that is not an object (`[1]`,
  `"x"`, `1`), panics with a plain error, which the catch chain turns into a 500. Rule: `Body()`
  panics with an `exception.Exception` of code 400 and message `Invalid JSON body`;
  `errors.As` on it reaches the `encoding/json` error. Over the body limit stays code 413
  (`*http.MaxBytesError`, as today); another read error is code 400 with message
  `Cannot read request body`.
- **B10** `ctx/http_body.go:28`, `ctx/http_form.go:24-26` (case-sensitive `strings.Contains`).
  `Content-Type: Application/JSON` gives an empty body and `Application/X-WWW-Form-Urlencoded` no
  form, while `text/plain; note=application/json` is parsed as JSON. Rule: the media type is the part
  before the first `;`, trimmed, compared case-insensitively. JSON is `application/json` or any
  `application/*+json` (`application/problem+json`); forms are exactly
  `application/x-www-form-urlencoded` and `multipart/form-data`.
- **B11** `ctx/http_form.go:30-32`. A form over the body limit or malformed (`a=%zz`, a broken
  multipart boundary) panics with a plain error: 500. Rule: `Form()` panics with an
  `exception.Exception`: code 413 when the cause is `*http.MaxBytesError`, else code 400 with message
  `Invalid form body`; `errors.As` reaches the cause.
- **B12** `ctx/http_form.go:34`. With no form content type `Form()` returns `nil` and is parsed again
  on every call; `Form().Set` panics. Rule: `Form()` never returns `nil` and is computed once.
- **B13** `ctx/http_file.go:36`. `File()` only reads `MultipartForm`, which nothing has parsed unless
  `Form()` ran first: a handler that injects `ctx.File` without `ctx.Form` gets no files from a valid
  multipart upload. Rule: `File()` parses the multipart form itself (same limits and errors as
  `Form()`); calling `File()` then `Form()`, or the reverse, parses once.
- **B20** `ctx/http_body.go:100-102`. `Body.Del("a.b")` deletes nothing although `Get`, `Set` and `Has`
  take dotted paths. Rule: `Del` removes the key at the path; a missing path is a no-op.
- **B21** `ctx/http_body.go:104-106`. `Body{"a": nil}.Has("a")` is `false` for a key that is present
  (`{"a": null}`). Rule: `Has` reports presence at the path, whatever the value.
- **B22** `ctx/http_file.go:64-69`. When `Store` panics the opened file is never closed. Rule: the
  source is closed before the panic leaves `File.Bind`.

### Bugs fixed: response and context
- **B15** `ctx/fn.go:18`. A raw JSON string always goes through `fmt.Sprintf`:
  `c.JSON(`{"rate":"100%"}`)` panics (`100%!"(MISSING)` is not JSON). Rule: with no `args` the string
  is used as is; with `args` it is formatted as today.
- **B16** `ctx/fn.go:15`. `c.JSON()` panics `index out of range`. Fixed by the signature.
- **B17** `ctx/http_context.go:84`, `ctx/fn.go:26`. The JSONP callback is only stripped of spaces:
  `?callback=alert(document.cookie)//` is echoed into a `text/javascript` response. Rule: every
  character outside `[A-Za-z0-9_$.\[\]]` is removed and the result is cut to 128 bytes; if nothing is
  left the response is plain JSON (B31). The response carries `X-Content-Type-Options: nosniff`.
- **B18** `ctx/http_context.go:99`. `c.Status(302).Redirect(url)` answers 301. Rule: `Redirect` uses
  `c.Code` when it is 300-399, else 301 (so a `POST` route, whose code `core` presets to 201, still
  answers 301). `c.Code` holds the code sent.
- **B19** `ctx/http_context.go:45-59`. `Reset` leaves `dataWriter` set: the pooled context keeps the
  last response's `ResponseWriter` and payload alive until its next write. Rule: see B27.

### Request ID and lifecycle
- **B24** `SetID` gives an ID of 8 lowercase hexadecimal characters (`requestIDLength`, unchanged),
  from `crypto.RandomHex(requestIDLength)` (design 0001), generated in `Init` (eager, see Open
  question 1 for the length). It is idempotent until `Reset`,
  ignores the `X-Request-Id` request header (unchanged), and 10,000 consecutive IDs hold at least
  9,990 distinct values. It never returns `""` and has no error path.
- **B26** `Init(w, r)` sets `Timestamp`, `ResponseWriter`, `Request`, the ID, and nothing else. `Code`
  is 200 after `NewHTTPContext` and after `Reset`.
- **B27** After `Reset` the context holds no reference to the request, the response writer, the
  payload or any parsed input. Fields that survive `Reset` on purpose: `scratch bytes.Buffer` (empty,
  capacity kept up to 64 KiB, see H1), `enc *json.Encoder`, and the capacity of two slices whose
  elements are cleared first: `ParamValues` (`len == 0` after `Reset`; design 0002 appends the next
  request's values into it, and its strings are substrings of the request path) and the aggregation
  list (B36). Named fields the tests may read:
  `scratch`, `enc`, `jsonValue any` (must be `nil` as soon as `JSON` returns or panics).
- **B28** A context that served request A and was `Reset` serves request B with no trace of A: ID,
  code, body, form, files, query, header, params, `Next`.

### Response writing
- **B29** `Text(data, args...)`: `Content-Type: text/plain; charset=utf-8`, status `c.Code`, body
  `data` as is with no `args`, `fmt.Sprintf(data, args...)` otherwise.
- **B30** `JSON(data, args...)`: `Content-Type: application/json`, status `c.Code`, body
  byte-identical to `json.Marshal(data)` (no trailing newline). Cases, in this order:
  1. `data` is a `string`: raw JSON (B15), validated and compacted by `encoding/json` as today.
  2. `data` implements `JSONAppender`: the body is what `AppendJSON` appends, trusted like a
     `json.Marshaler`.
  3. anything else is encoded.
  When encoding fails (unsupported type, invalid raw string, a failing `MarshalJSON`), `JSON` panics
  with an `exception.Exception` of code 500 whose chain holds the `encoding/json` error, and nothing
  has been written: no header, no status, no byte.
- **B31** `JSONP(data, args...)`: with a callback left after B17, `Content-Type: text/javascript;
  charset=utf-8`, `X-Content-Type-Options: nosniff`, status `c.Code`, body exactly
  `/**/ typeof <cb> === 'function' && <cb>(<json>);` where `<json>` is B30's body. Without one it is
  B30. The callback is read from `c.Query()` (cached), not parsed again. U+2028, U+2029, `<`, `>`,
  `&` stay escaped in `<json>` for both raw strings and encoded values (true today; pinned).
- **B32** The `Content-Type` header holds exactly one value; a later `Header().Add("Content-Type", …)`
  or `Set` on one response never changes what another response gets (H2).

### Accessors
- **B33** `Query()` is `URL.Query()` cached per request (unchanged). `Param()` builds
  `Param{key: values}` from `ParamKeys` / `ParamValues` once per request, with values copied (the map
  stays valid if the router reuses its slice). `Header()` is the request header (unchanged).
- **B35** `ctx/http_param.go:15` indexes `ParamValues` without a length check. Rule: an index in
  `ParamKeys` that is outside `ParamValues` is skipped; `Param()` does not panic.
- **B36** `AddAggregation(a)` appends to a per-request list; `Aggregations()` returns the list in that
  order, `nil` or empty when there is none. `Reset` empties it (elements set to `nil`, capacity kept):
  a context reused after `Reset` starts with no aggregation, and a warm context adds without
  allocating. The same on `WSContext`.
- **B34** `Body.Get / Set / Has / Del` split the path on `.` and ignore segments that are blank after
  trimming; kept segments are not trimmed. `Get("")` returns the body itself. A path without a dot
  behaves as a plain map key (fast path).

### Heavy techniques (approving the design approves exactly these)
- **H1: one hand-managed buffer per pooled context.** `HTTPContext` gains `scratch bytes.Buffer` and
  `enc *json.Encoder` (bound to `&c.scratch`, created on the first `JSON` of that context). `Body()`
  reads the request body into it, then `JSON` / `JSONP` encode the response into it; the two uses
  never overlap in time. It rides on the existing `core` context pool: no new `sync.Pool`.
  Justified by P3, P5, P7. Constraints: the bytes are valid only until the next use, so nothing may
  keep a slice of `scratch` (the body map copies its strings; the response is written before `JSON`
  returns); `Reset` drops a buffer whose capacity grew past 64 KiB (`c.scratch = bytes.Buffer{}`), so
  an idle pool holds at most 64 KiB per context; the encoder's trailing newline is cut before the
  write.
- **H2: shared read-only header values.** Package-level `[]string{"application/json"}`,
  `[]string{"text/plain; charset=utf-8"}`, `[]string{"text/javascript; charset=utf-8"}` assigned with
  `h["Content-Type"] = v` (Gin does the same). Justified by `Header.Set` 65 ns, 1 alloc → assignment
  14 ns, 0 allocs, on every response. Constraint: nobody may write `h["Content-Type"][0] = …` in
  place; `Set`, `Add` and `Del` are safe (`Add` reallocates because length equals capacity). B32
  tests it.

- **H3: two slices that keep their capacity across requests** (`ParamValues`, the aggregation list),
  on the pooled context. Justified by design 0002 (its H1: 163 ns + 1 alloc → 120 ns + 0 allocs per
  parameter route) and design 0005 (interceptor dispatch). Constraints: `Reset` clears the elements
  before cutting the length, so no path string or aggregation outlives its request; `ParamValues`
  and `Aggregations()` are valid only during the request (`Param()` copies, B33); each slice is
  dropped when its capacity passes 64 entries.

No `unsafe`, no new `sync.Pool`, no inlining restructure. Considered and rejected: an ID string that
aliases a buffer inside the pooled context (the response header and async log handlers outlive the
request), pooling `[]FieldLevel`, a custom query parser (see above).

Every fast path has an equality test (Test plan, "Fast path equals slow path").

## Concurrency
- A context belongs to one request and one goroutine at a time. `core` takes it from the pool, calls
  `Init`, runs the pipeline, calls `Reset`, puts it back (`core/app.go:162-163`, `572-575`). Handler
  code must not keep the context, or anything it returned that aliases it, after the request ends;
  the README says so. `GetID` is a pure read after `Init` (the reason the ID is not lazy: a lazy ID
  would make `GetID` a write, and handlers do start goroutines that log it).
- The binder cache is a `sync.Map` keyed by `reflect.Type`; a `*Binder` is immutable once stored and
  safe for concurrent use. Two goroutines building the same type both succeed; one result is kept
  (`LoadOrStore`).
- The shared header slices of H2 are never written.
- The ID source must be safe for concurrent use without a lock (see Impact).

## Security
- **Limits first.** The body is capped by `core` (`http.MaxBytesReader`, 10 MB default,
  `core/app.go:158-160`) before `ctx` reads it; `Body()`, `Form()` and `File()` turn the limit error
  into 413 (B9, B11). The scratch buffer grows with what is read, never from `Content-Length` (a
  client could otherwise make the server allocate 10 MB per request by declaring a length and sending
  nothing). Multipart keeps at most the body limit in memory (`defaultMaxMemory` 32 MiB is above it).
  JSON nesting is bounded by `encoding/json` (10,000 levels) and the body limit; the binder recurses
  only as deep as the data.
- **Hostile input never panics with a runtime error** in binding (B2-B7): wrong types, `null`,
  out-of-range numbers and unsupported element kinds leave the field zero.
- **JSONP** callback is reduced to identifier characters, capped at 128 bytes, served with `nosniff`
  (B17, B31).
- **Header injection:** `ctx` writes only constant header values. `Redirect` passes the target to
  `http.Redirect`, which escapes it; `net/http` refuses CR and LF in header values. `Redirect` does
  not check where the target points: validating a user-supplied URL (`//evil.example`) is the
  handler's job; the README says so.
- **`JSON` with a format string** inserts `args` unescaped: it is for trusted values only (README).
- The request ID is a correlation ID, not a secret: it is not cryptographically random anymore (P1).
- File names come from `multipart.FileHeader.Filename`, which the standard library reduces to a base
  name.

## Impact
- **`internal/crypto` (design 0001).** `ctx` uses `crypto.RandomHex(8)` (8 lowercase hexadecimal
  characters, no error, no shared lock, one 8-byte allocation, 24 ns in 0001's prototype) and nothing
  else from `crypto`. `AppendRandomHex` into a buffer owned by the context is not used: the ID string
  must outlive the pooled context (response header, async log handlers).
- **`core` (unchanged in this step).** All calls compile. For roadmap 0003: `core/app.go:193` can
  write the ID header with `w.Header()[ctx.RequestID] = []string{id}` (the key is already canonical),
  and `core/default.go:28`, `core/http.go:252` can pass an exception to `c.JSON` (design 0004).
- **`routing` (design 0002).** `ctx` keeps reading `ParamKeys map[string][]int` and
  `ParamValues []string`; `Param()` copies the values and `Reset` keeps the slice's capacity (P10), as

## Open questions
1. **Request ID length.** 8 hexadecimal characters are 32 bits: two requests share an ID after about
   77,000 requests on average (a minute or so at 1,000 requests per second). Keep 8 (short log
   lines, no visible change) or move to 16 (same single allocation, 16 B)? Recommendation: 16; the
   design keeps 8 until you decide, and only `requestIDLength` and the `crypto` contract change.
2. **Bind without `[]FieldLevel`.** Most pipes discard the field levels (`bound, _ := q.Bind(dto)`),
   yet they cost half of a bind (2 fields: 310 ns, 4 allocs with them; 145 ns, 2 allocs without).
   Add `BindValue(s any) any` to `Query`, `Form`, `Header`, `Param`, `Body`, `WSPayload`?
   Recommendation: yes, as a follow-up inside this step if you approve (six one-line wrappers over the
   binder); not included in the rules above.
3. **B18 changes what `Status(3xx).Redirect` answers** (today always 301). Recommendation: accept; no
   caller can rely on a status being ignored.
4. **B7 keeps truncating fractions** (`1.9` → `1` for an `int` field) and only refuses out-of-range
   numbers. Refusing fractions too would be stricter but changes results that are well defined today.
   Recommendation: keep truncation.

## Decisions (2026-11-16)

Approved by Claude under the user's one-time delegation for roadmap 0002 (see its Log). Heavy
techniques are **not** approved: they are built without and listed as proposals for the user.
The open questions above are answered as follows.

- Q1 request ID: 16 hex characters, `crypto.RandomHex(16)` (64 bits; `RandomHex(n)` returns `n`
  characters per design 0001 K2), generated eagerly in `Init` as designed.
- Q2 add `BindValue(s) any`: yes, with rules and tests like the other bind functions.
- Q3 `Status(3xx).Redirect` honors the status: yes.
- Q4 fractions keep truncating; out-of-range numbers are a bind error (see 0001 Q3).
- **H1 (scratch buffer and kept encoder per context): not approved.** `JSON` marshals with
  `encoding/json` (the per-type pointer / value choice of P3 is a plain branch and stays); `Body()`
  reads with `io.ReadAll` as today.
- **H2 (shared read-only header slices): not approved.** Headers are set by direct map assignment
  with a fresh one-element slice (no canonicalization: the keys are already canonical).
- **H3 (capacity kept across requests): not approved.** `ParamValues` and the aggregation list are
  cleared to nil in `Reset`, so nothing is retained by a pooled context.
