# HTTP report 0012: security

Roadmap `docs/roadmap/0012-security.md`, step 11. Test binaries of `7cb0634` (before the roadmap's code)
and `48fd1c1` (after the audit fixes) run alternately, six rounds, the order swapped every round,
compared with `benchstat`. Go 1.27.4, Intel Core i7-9750H, macOS; the machine was busy (spreads up
to ± 19 %), so differences under about 10 % are noise.

## Hot path (`bench/`)

Every scenario is within noise (geomean +0.7 %, no significant change); allocations and bytes per
request are identical in every scenario. The static-name policy and the redirect check run only on
static routes and on redirects, so API routes pay nothing.

## Cold path

| Measure | Before | After |
|---|---|---|
| `Create`, five controllers | 61.7 µs, 32.1 KiB | 62.2 µs, 32.8 KiB |
| `Create`, chained providers | 168.3 µs, 87.1 KiB | 164.4 µs, 87.2 KiB |
| `Create`, static submodules | 191.2 µs, 133.1 KiB | 189.2 µs, 133.2 KiB |
| `Create`, module factories | 237.3 µs, 15.1 KiB | 255.2 µs (+7.5 %, p=0.04, inside the ± 19 % spread), 15.3 KiB |
| Idle heap of a small app | 13.0 KiB | 13.2 KiB |
| Idle heap with one page (benchmark) | 165.6 KiB | 167.7 KiB |
| Binary of `examples/01-hello` | 16.5 MiB (11.3 MiB stripped) | 16.5 MiB (11.4 MiB stripped) |

`Create` keeps about 0.1 to 0.8 KiB more (the `ServeDirs` table, the guard coverage check); the idle
heap grows by 0.2 KiB. Recheck `Create` with factories on a quiet machine with the next measurement.

## Static file benchmarks (audit 0012, L9)

Added after the roadmap: `BenchmarkServe_File` (a `SERVE_` file from a temporary directory),
`BenchmarkAsset_PageGuarded` (a page's CSS behind one route guard) and `BenchmarkPublic_File`
(`/robots.txt` from `public/`), in `internal/core/http_static_bench_test.go`. Base: `7cb0634` (before
the security changes; the same file without `ServeDirs`), in a git worktree, alternating runs.
The machine was busy (load average 5 to 8), so only differences with a small spread count.

| Benchmark | `7cb0634` | After | Note |
|---|---|---|---|
| `Serve_File`, 12 CPUs | 87-91 µs, 2.5 KiB, 39 allocs | 72-77 µs, 1.8 KiB, 26 allocs | faster, 13 allocations fewer; the cause is not analysed |
| `Asset_PageGuarded`, 12 CPUs | 2.0-2.2 µs, 1145 B, 13 allocs | 2.3-2.5 µs, 1130 B, 12 allocs | the page's guards run on its files since step 7 (G5); p = 0.06, ± 20 % |
| `Public_File`, 1 CPU, 10 alternating runs | 5.50 µs ± 4 %, 14 allocs | 5.34 µs ± 2 %, 13 allocs | no difference (p = 0.35) |

Allocations went down by one on each static route. A run at 12 CPUs showed `Public_File` 13 to 40 %
slower with a ± 20 % spread; the alternating one-CPU run shows no difference. Recheck at 12 CPUs on
a quiet machine with the next measurement.
